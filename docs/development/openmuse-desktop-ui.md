# AcceptCat 0.8.0：OpenMuse风格桌面界面

## 范围与来源

2026-10-09用户要求用OpenMuse改善老旧UI，并明确继续做Windows桌面。基于0.7.0科研规划，继续使用React18 / Vite / Electron22和现有OpenIM原生SDK。没有迁移账号、联系人、模型配置、任务后台或数据库。

参考[CopilotKit/openmuse](https://github.com/CopilotKit/openmuse/tree/1ac68f3909f2478ab6280883f1ab5ea65eb5719d)固定提交 `1ac68f3909f2478ab6280883f1ab5ea65eb5719d` 的 `apps/mobile/src/ui.tsx`、`chat.tsx`、`App.tsx` 与官方界面。上游UI实际采用React Native / Expo，不可直接替换当前DOM组件；本批移植浅色主题、柔和消息卡片、居中聊天区和浮动输入区的设计方式。没有新增React Native、CopilotKit Intelligence、AG-UI或A2A依赖，流式回复和任务状态仍通过既有科研服务协议传递。

OpenMuse的MIT说明保存在 `clients/openim/public/third-party/openmuse/LICENSE.txt`，并随构建静态资源保留；现有OpenIM派生部分继续保留自身来源与许可。

## 已改界面

- 左侧浅色76px导航，消息、通讯录、工作台、广场及设置，现有更新提示保留。
- 248px聊天列表，搜索、新建、置顶标记、柔和选中态；支持收起和重新展开，收起不改变当前会话或SDK状态。
- 居中联系人头像与标题，右上“聊天详情”；正文区域最大840px，个人私聊隐藏重复姓名行，群聊保留成员姓名。
- 灰色Agent消息、浅蓝本人消息，圆角23px，正文15px / 1.65行高；统一头像圆形，但保留本人真实图片或已有首字，不使用概念图虚构头像。
- 浮动圆角28px输入框、桌面图标工具栏、圆形发送按钮；维持Enter发送、Shift+Enter换行、持续输入、引用、原消息重试。失败记录和引用动态增高，窄窗口可滚动查看。
- 工作台、计划列表、步骤表单、通讯录、广场、详情抽屉和设置采用同一配色。保留计划生成记录、待澄清、保存、确认任务、日期、依赖、负责人和验收字段。
- 本地文件夹、附件、语音、文件报告与可选协作仍按现有身份、权限和能力条件出现。没有把缺少授权的测试状态伪装成可用工具。

使用frontend-app-builder / ImageGen设计流程，先生成聊天、工作台完整概念，再提取统一token并实现。概念与截图保留在Git外 `D:/deepseek-agent/.runtime/openmuse-desktop-20261009/`：`chat-concept.png`、`workbench-concept.png`。参考截图与上游源码研究快照另存 `.runtime/openmuse-comparison-20261007` / `.runtime/openmuse-ui-study-20261009`，没有复制其测试素材进入产品。

| 工作台 | 同色系计划列表与编号步骤，宽窗口双列字段、窄窗口单列；保留实际必需的表单操作与纵向滚动 |

`view_image`已在同一收尾轮查看概念和最终实际截图，包括聊天1600×1000、聚焦模式、失败恢复1024×726、工作台1600×1000 / 1024×726、通讯录和设置入口。已按上述构图、字体、配色、间距、圆角和交互核对设计实现；没有尚未修正的主要视觉问题。概念原生1586×1000与实际1600×1000差14px宽，另外检查最小桌面窗口1024×726；按用户范围没有增加手机版设计。

文案差异：保留既有消息 / 通讯录 / 工作台 / 广场 / 设置与五个工作台页签；新增“聊天”“我的计划”“收起/展开聊天列表”，目标标签明确为“计划目标”，发送改图标但保留“发送消息”辅助标签，聊天菜单明确为“聊天详情”。概念里的虚构论文、步数、日期、已读回执和第二条计划没有填进实际数据。实际步骤目标、移位/删除、草案分类、分页和生成记录为已有操作，继续保留；真实数据为空时显示真实空状态。

有意差异：OpenMuse的单会话/底部工具坞适配为AcceptCat多联系人IM左导航；聊天列表较概念更窄以照顾1024窗口；Agent能力、文件工具只在现有授权满足时出现；头像保持本人身份，消息内容使用独立合成材料，科研计划允许纵向滚动。没有宣称对OpenMuse截图逐像素复制。
