# AcceptCat：科研任务规划（Windows 0.7.0）

本批在桌面工作台串起现有计划、后台规划请求、分步任务与结果验收接口。共享契约仍为0.22 / chat1.11 / schema21，无数据库迁移。实际安装包、固定源码与线上版本以[当前状态](../current-state.md)为准。

## 参考依据

用户要求参考Today并直接改进任务规划。阅读了Today的[中文文章目录](https://today.ai/articles/zh-Hans)、[产品介绍](https://today.ai/articles/zh-Hans/blog/what-is-today)和[个人Agent使用场景](https://today.ai/articles/zh-Hans/blog/personal-ai-agent-use-cases)。借鉴公开说明中的多步骤计划、明确完成条件、可检查的结果和持续的下一步提示；没有登录Today或把营销页面当成实测产品证据。

在AcceptCat中具体落到科研工作：目标 → 可编辑的步骤 → 分工与依赖 → 保存草案 → 明确确认 → 真实任务 → 提交成果 → 验收 → 下一步。未知日期、成员是否承接、执行是否完成都按实际记录展示。

## 使用方式

1. 左侧工作台默认打开“任务规划”，点击“规划新任务”。已有单项任务在“我的任务”中继续管理。
2. 写目标，可补充最终交付物和截止日期。选择“让AI拆成步骤”，或者使用论文阅读、实验推进、论文写作模板；也可以从空白步骤填写。
3. 调整每步的名称、目标、交付物、验收标准、负责人、前置步骤与日期。顺序可调整；删除步骤会明确移除相关依赖。循环依赖、缺失依赖、重名步骤和空白关键字段会阻止保存 / 确认。
4. “保存草案”写入服务端。保存后关闭再打开，可从左侧找回。未保存的编辑需要先保存；窗口关闭或离开工作台没有跨重启恢复保证。列表内切换计划、替换模板会确认是否丢弃未保存编辑。
5. “确认并创建任务”会保存并确认同一版本，再创建实际步骤任务。受邀成员接受后才成为承接者；公共Agent步骤会建立执行请求，没有材料时等待输入。每步保留独立预算，结果仍需验收。
6. 已确认计划显示实际状态、承接者、截止日期与已验收步数。“处理这一步”打开已有任务面板，补充材料、执行、提交和验收继续沿用权威任务服务。执行结束、模型回复或提交成果均不会自行标成已完成。

AI请求记录在服务端保留，可以读取进度、停止生成、重新打开产生的草案。失败不创建假任务，输入保留供调整或使用模板；不会自动重复模型请求。其他窗口更新草案时提示版本变化，采用最新版本前确认替换；读取失败 / 撤权时隐藏已读取的计划事实，保留编辑用于恢复。

## 当前边界

- AI拆解复用现有B3科研规划worker及实验室规划模型配置，尚未迁移到“模型设置”中的个人默认模型。不能把合成模型验收当成当前账号真实供应商可用的证明。模板和手工填写不需要模型。
- AI截止日期作为需求建议传入，现有worker可能返回空时间安排；需要在生成草案中核对并填写。模板直接保留用户明确填写的日期；没有日期不会推测。
- 此规划入口可分配本人、同实验室成员和现有已发布公共能力；尚不能选择任意私人Agent联系人或跨空间好友。已有私人Agent协作可继续从单项任务入口使用；不宣称本批完成全部自动匹配和跨小组协作。
- 本批不增加文献检索、实验执行、绘图、任意本地脚本执行、自动整项目推进或新的定时提醒。原有聊天、私人Skill、定时任务和本机报告保留。
- 成员选择读取前100名；计划列表每页30项，搜索明确限定当前页；AI记录每页10项。确认计划的步骤对应目前按planId和唯一、不可修改的任务标题匹配，最多扫描2000个本人授权任务。找不到或有歧义显示未读取，不编造进度。
- 草案步骤ID和确认后的任务ID不同。前端读取真实任务，不能拿草案ID当任务ID。
- 本批只制作Windows本地安装候选；服务器、数据库与公开更新Release分别记录，不能由客户端版本推断后台已升级。
