# Windows 图片粘贴与批量识字

AcceptCat 0.8.1 本地候选，基于 0.8.0 的 OpenMuse 风格桌面。只修改客户端，不依赖新的 API、数据库迁移或模型 Key。

**0.8.2更新：** 发给本站Agent的单聊图片已接入自动本机OCR和回复；旧图片支持“识别并回复”与原图本机恢复。[新版流程及验证](agent-image-replies.md)。下文保留0.8.1原始行为与验证记录，“单发图片只作为IM消息”是该旧版本的边界。

## 使用流程

1. 在聊天输入区按 Ctrl+V，或点击工具栏的“粘贴图片”。也可以点击“图片”多选文件，或拖入图片。
2. 待发送图片按顺序预览，可以逐张移除。粘贴不会自动上传或发送。
3. 点击“识别文字”，逐张在 Windows 本机识别。结果可以编辑、复制或保存为 TXT。
4. 点击“插入聊天”，将已核对文字放入草稿；补充需求后再发送给 Agent。也可以单独点击“发送图片”。单发图片仍是 IM 图片消息，不会伪装成已读过图像的 AI 回复。

一次最多 20 张，每张 10 MiB，总计 50 MiB。图片识字支持 Windows 10/11，优先使用已安装的中文识字语言，否则使用系统语言，并提示中文语言包要求。长图按重叠片段覆盖到底部，合并重叠文字；超过 3000 万像素或任一边超过 40000 像素拒绝。文字超过 7500 字符时须保存或分段复制；不静默裁掉后面的识别结果。数字、中文复杂字、专有名词和模糊原图仍需人工校对。

## 微信复制边界

支持标准位图剪贴板，以及 Windows CF_HDROP 多文件列表。微信多选如果只产生微信内部的消息记录，不能保证转换成多张原图；界面明确提示先保存图片，再从文件夹多选复制或拖入。未逆向微信私有格式、读取微信数据库或实测用户微信剪贴板。普通文字保留原 CKEditor 粘贴逻辑。

## 实现与验证

输入区在 CKEditor 文字插件丢弃图片前捕获粘贴；图片选取、拖入共享本机预览。图片没有本地路径时，通过字节桥接写入原生 SDK 缓存再发消息，不向 contextBridge 传递不可克隆的 File 实例。切换会话/账号时取消旧操作、销毁预览 URL，不把旧结果插入另一个联系人的输入框。

原生读取只接受活动主窗口和服务来源；本地路径仅来自系统剪贴板，不能由 renderer 请求任意路径。文件数量/大小、输出、像素和识别总时间有上限。WinRT OCR 在隐藏 PowerShell 子进程中执行固定程序、读取图片字节；不继承账号/模型凭据环境，不读取远程 URL，不执行图片中的文字，结果不自动发送。取消会终止子进程。识别失败保留图片和明确重试；失败、未完成或空文字时不能插入聊天。

四项单元检查包含真实 Windows DragQueryFileW/Unicode DROPFILES（使用独立内存句柄，不碰系统剪贴板）、数量与路径上限、长图覆盖和去重。另六项发送恢复检查通过。隔离 Electron22 的生产聊天组件、真实 preload/IPC/Windows OCR 和本地 HTTPS/API 验证九条流程：文字粘贴、多图预览、中英文数字及长图底部、编辑插入、原发送队列、无路径图片消息、损坏图错误、最小窗口、切换联系人清理。IM 回执是合成夹具，非生产 IM/模型验收。

测试图为合成 900px 宽图和 5500px 高长图。实际文字包括 `AcceptCat research notes`、`12345`、`67890` 及长图的开头/中段/底部；中文“识别”和“边界位置”有误识，已保留真实结果，不能据此宣称 OCR 完全准确。

证据在 Git 外 `D:/deepseek-agent/.runtime/image-paste-20261009`：OCR 原文、合成图、界面截图、九项报告、构建日志。Browser 插件未提供可用的独立测试能力且原生 CUA 禁用，使用 Playwright 控制隔离 Electron；未操作用户微信、系统剪贴板、真实账户、模型 Key 或研究资料。测试宿主的跨来源静态图标缺失和截图刷新延迟不属于正式打包 UI；新安装包登录与桥接另行核对。初次打包的跨目录运行时常量遗漏已修复；夹具的本地 TLS 信任和路径失败记录保留，不计通过。

当前发布状态及精确安装包见 [交接入口](../current-state.md)。用户安装版覆盖升级、真实微信私有复制格式及不同系统语言包尚未实测。
