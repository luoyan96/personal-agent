# Personal Agent 对话上下文

本批只改共享 API/worker 的上下文拼装。现有 Windows 0.5.1 继续使用相同协议；没有增加桌面安装包、公开接口或数据库迁移。contract0.21/chat1.10/schema20 保持。部署状态与固定源码看 `docs/current-state.md`，不能把本地测试当成生产上线。

## 实际五层

1. **当前身份**：当前请求的 Agent 介绍、能力、性格，以及有权限查看的联系人资料。沿用原有版本与权限检查。
2. **近期原文**：普通本地聊天候选窗口从20扩大到80条。连续输入的本轮全部消息始终优先、完整保留，即使超过80条；预算不足会拒绝调用，不截掉用户当前输入。预算挑选中的历史原文也不截断。
3. **较早对话摘要**：从近期窗口之前至多320条可读消息抽取带出处的原话片段，优先保留决定、待确认问题与需求，最多8个候选。每段含消息编号、序号、说话者、来源类型和是否只是片段。分类是启发式，不代表事实已经确认，也不是模型新写的结论。
4. **相关历史与记忆**：按当前问题，在同一对话全部历史中进行关键词/中文重叠双字匹配；按相关度而非单纯时间挑选至多256条候选，再经真实消息权限投影、排序、选择至多8个片段。本人确认过的长期记忆按回复方式/称呼/语言及当前相关性选择，最多12条且JSON内容至多3500字节。省略时告知模型还有其他记忆，原记录不会删除。候选记忆不自动升级成已确认事实。
5. **任务工作状态**：本人助理使用关联本对话或由本对话发起的本人工作任务；专题聊天和协作群只使用关联当前聊天、当前查看者有完整权限的工作任务。保留实际目标、成员及其接受状态、当前状态、结果出处、是否验收与下一步。最多40/20个任务候选，最终至多5个且仍受本轮预算约束。研究任务/材料继续走已有显式授权 `context`。本地文件夹报告不是后台能自动扫描的内容。

文件阅读继续先给本轮完整输入和授权文件提取文字分配空间；旧聊天、摘要和任务状态只使用剩余空间，不把完整论文挤成第一页。

## 连贯性与撤回

- 摘要和历史检索均从持久化的原消息按需生成，重启后可重新构建。没有新增一份长期保存的私人聊天摘要，也没有额外摘要/向量模型调用。
- 记录实际送入模型的历史消息来源及指纹、任务来源及版本。生成期间来源或任务变化，旧结果被取消；迟到的实际用量仍记账。
- 记忆管理消息及其确认回执不会再被当成普通聊天记忆。回复记录其实际使用的个人/Agent记忆及版本；纠正、撤回或失效后，依赖旧版本的回复从自动上下文和任务结果摘录中移除。没有依赖清单的旧版个人记忆回复，按整体记忆指纹保守失效。原聊天审计历史没有删除。
- 当前用户输入、已确认记忆、当前任务状态优先。旧聊天、模型答复、文件及检索片段都不能授权创建联系人、转发、定时安排、工具执行或宣称完成。
- 普通本地对话不会自动混入另一对话的私人历史。外部 Agent 接口仍只接收本条明确同意外发的文字，不增加聊天历史、记忆、文件或任务转发。

## 长度与费用

新建的普通本地 `agentChatMessage` 总预算为16000 tokens/90秒，输出上限仍4096 tokens。创建 Agent、助理协调、外部接口、定时请求、显式协作预算和文件阅读预算沿用已有规则。合并到已有队列、旧4000请求以及重试不会自动提高原授权预算。

仍使用 UTF-8 字节+256 的保守输入准入上界，并最终核对供应商实际输入/输出用量。它不是供应商实测tokenizer，也不能将未知供应商按英文字符比例假装精确计量。较大的普通聊天总上限允许更多上下文，也可能增加调用费用；没有提高单次输出上限或重复后台调用。

## 验证与边界

`apps/api/tests/dialogue-context.spec.ts` 使用真实HTTP、持久化SQLite和生产ChatWorker，供应商结果明确为合成。覆盖超过640条消息后的原话找回与早期决定摘要、实际关库/重新打开后的找回、不同用户/对话隔离、来源修改时取消迟到结果、中文主题片段匹配、记忆更正/撤回、真实任务验收变化、完整连续输入与原队列预算保持、外部授权范围、较大记忆集合以及协调模式的历史授权边界。

历史检索是可解释的关键词匹配，还不是语义向量检索。摘要是带出处的有界摘录，还不是跨全部档案的模型总结。不能承诺永久完整回忆、OCR或自动扫描未授权文件夹。自然语言回答质量仍取决于用户所选模型；本批没有使用用户API Key或真实材料进行模型质量评估。
