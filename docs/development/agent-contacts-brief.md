# 人与 Agent 联系人、持续档案与需求协调

日期：2026-10-04。用户明确要求继续修改并由总控安排前后端：人和 Agent 都作为 IM 联系人，有稳定身份、介绍、能力、性格和记忆；任务能力匹配在外部体现为固定置顶的需求对话框。

## 共同起点

基线 `be8ccc2`，现有 OpenIM 风格 TypeScript 界面与科研服务。保留消息、未读/置顶、独立入群与任务承接、材料授权、受控 worker 和成果状态。开发目录仍使用现有前后端独立克隆，新分支以本文件所在总控提交为起点；不重置已有目录。不自动推送 GitHub 或部署。

## 本批交付

1. **统一联系人。** 人和 AI 共用通讯录、发现/添加、档案和聊天入口。保存真实联系人关系，真人由对方接受、私人 Agent 由负责人接受；本人 Agent 和已发布的本实验室公共 Agent 可直接添加。已有真人私聊关系兼容保留。目录发现与“我的联系人”可分别查看；入通讯录、入群、任务承接分别处理。
2. **持续档案。** 统一介绍和能力介绍；Agent 另有稳定 ID、负责人、角色与性格/工作方式。本人真人资料及本人 Agent 可编辑，公共 Agent 由实验室负责人维护。能力介绍是设定描述，实际可执行能力仍由既有运行服务决定。保留头像/身份可辨认，不声称虚构在线状态。
3. **设定专属 Agent。** 可以创建本人负责的专用 Agent，填写名字、介绍、能力介绍和性格；稳定 ID 与本人固定协调 Agent 区别保存，使用现有 personal_agent 身份扩展。所有 Agent 实际调用继续用已配置的实验室模型，不增加模型供应商或自行读取生产 Key。
4. **可检查的持续记忆。** Agent 负责人可添加、编辑、移除该 Agent 的私有记忆；群内/会话共同记忆绑定特定会话并经授权维护。记忆有内容、来源/范围、版本与实际存储，跨刷新/进程重启保留。私有记忆仅用于负责人本人个人/专属对话；他人私聊与群聊只使用当前获准会话记忆，不能把负责人私聊和记忆隐式分享。首版明确由用户保存，不伪造自动学习或已记住。
5. **模型实际使用档案/记忆。** ChatWorker 提供稳定 Agent 档案、当前角色、设定性格/能力及按范围筛选的持久记忆；视为用户设定数据，保留系统与业务权限。用注入 ModelCall 捕获输入证明它们实际进入上下文、历史截断后仍有记忆、群/他人排除私人记忆；编辑冲突和撤权需阻止过期写入/输出。
6. **置顶需求入口。** 当前唯一个人助理升级为协调角色，前端会话行清楚标“需求与协作”，展示真实 Agent 名字。默认打开且永远第一。需求澄清、匹配成员、群建议沿既有模型协议和确认/建群事务继续实现，依据联系人真实档案/能力与可用状态匹配。其他 Agent 的私聊/群回复以自身角色响应；不能全都伪装协调入口。

## 验收要点

真实用户创建 Agent→填写/更新档案→保存私有记忆→刷新/重启→同一 Agent 能继续使用该记忆；其他成员查看公开档案、申请添加，经负责人接受后可私聊，模型看不到负责人私人记忆。已有任务群可查看/维护共同记忆，撤权后不可读取/更改。置顶需求协调角色可据能力档案建议人/AI 建群，原有独立邀请、材料授权和交付闭环回归通过。模型网络验收与合成输入验收分别报告，无凭据时如实保留未验证状态。
