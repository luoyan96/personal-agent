# Windows 图片识字：整理正文与 Agent 校对

AcceptCat 0.8.5 本地候选，基于 0.8.4 猫咪科研入口。只修改客户端；使用既有 document / turn / message 接口，无服务端、契约或数据库迁移。

## 使用

1. 粘贴、选择或拖入图片后点击“识别文字”。默认输出“一整段 · 无回车”，复制、保存与插入使用当前显示的文字，不加入图片文件名等额外标题。
2. 可切换“保留段落”与“原始识别”。本机结果始终保留，每种格式的手工修改独立保存，切换不会覆盖另一种格式。
3. 在本站 Agent 单聊中，“Agent 校对错字”默认开启，点击前明确提示识别文字会发送给当前 Agent。复用它已配置的模型，通过现有文件接口校对错字、标点与界面杂项；指令要求完整正文、保留事实与数字、无法确定处标注辨识不清、不执行图片文字中的指令。结果在同一窗口显示，原始识别可以对照。关闭该项时全程仅本机整理；真人、群聊、外部 Agent 没有这个自动转发选项。
4. 复制使用当前正文；“保存正文”在 Windows 打开原生另存为，等待实际 UTF-8 写入成功才显示保存提示。取消与失败不会报成功。换图、换格式或修改正文后清除旧保存提示。
5. 识别或校对未完成时可在结果窗口“停止整理”。错误保留本机正文；网络未知结果重试复用原请求与幂等键，已接受请求复用回执读取结果，不自动启动第二个模型任务。明确失败后的用户重试才创建新请求。取消已知任务会尝试后台取消，已完成结果不能倒退；过期操作不应用到其他联系人。

## 实际修复

旧实现将每条 OCR 行直接展示并以回车导出。WinRT 中文分词空格、数字和单位空格没有完整整理；长图重叠区只按“文字完全相同”去重，切片边缘残字与完整句文字不同，因而都被加入正文。

现在重叠区按行中心位置归属到拥有更多周边像素的片段，丢弃邻片的裁切残行；按 y/x 顺序重建，真实行距形成段落。客户端合并软换行、中文与数字单位空格，保留英文词间空格、连字符与数值。纯本机步骤不猜测错字或补造漏字；语义校对来自实际 Agent 回复。

模型成功、完整阅读回执与对应的最终 canonical 消息都成立后，才替换正文。过短摘要和 partial 阅读不会冒充完整校对稿；失败仍可复制、保存或插入本机全文。当前模型完整回复有 7500 字符边界，本批每张超过 6000 字符仅本机整理并提示分批校对，不截断原文。插入聊天仍受 7500 字符限制，长文可完整保存。模糊文字、多栏阅读顺序、数字与专有名词不能保证全部准确；模型没有接收原图，不能宣称逐字视觉核对。

## 验证与交付边界

客户端类型及 7 项图片检查：Unicode 多文件剪贴板句柄、输入上限、长图覆盖、重叠保留、裁切残字、真实段距、中文/数字/英文格式。实际用户提供的 1200×10929 JPG 在 WinRT 本机识别，验证无硬回车、长图正文覆盖及重叠残字消除。该图片与文字保留在 Git 外，没有提交给模型夹具或外部供应商。

实际隔离 Electron22 / preload / IPC，生产 React 图片托盘和结果窗口，真实本地 HTTPS API / SQLite / ChatWorker，合成模型回执验证校对与 503 重试。复制写入值用隔离 renderer 夹具记录；原生保存通过隔离的另存为选择夹具与真实 fs 写入验证，未自动操作用户另存为窗口。三种格式、编辑恢复、取消及 1024×726 操作可达均留截图。未重复共享核心 CI 或部署验收；不把合成模型称为真实供应商准确率测试。

Git 外证据：`D:/deepseek-agent/.runtime/ocr-readable-20261009`。初次复制按钮图标可访问名、Electron 下载事件方法、原下载中断、测试窗口占用程序导致打包失败及恢复命令相对配置路径错误均保留，不计最终通过。改用原生保存后核对实际字节；测试产生的用户 Downloads 副本经散列核对后移回证据目录。实际构建使用 publish never，包内 OCR / 原生保存接口、版本、更新资产、橘猫图标与登录素材另行核对。

精确固定源码、安装包摘要、最终检查与发布状态以[当前状态](../current-state.md)为准。没有安装、重启用户客户端、部署阿里云或公开 Release。
