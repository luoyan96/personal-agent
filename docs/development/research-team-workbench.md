# AcceptCat 科研团队工作台

## 本轮用途

教师和学生在同一课题组账号内完成：目标 → 编辑计划 → 确认分工 → 本人接受 → 开始任务 → 提交成果 → 导师审阅 → 修改 / 验收。科研工作台以真实成果和下一步对齐，不以聊天数量作为进展。

桌面0.9.0、contract0.23.0、schema021。安装包已完成，配套 API / worker 已部署；精确源码、镜像、安装资产和边界以 `docs/current-state.md` 为准。尚未公开 GitHub Release。

## 使用

1. 负责人通过已有邀请管理签发课题组邀请码，学生用该码注册同一课题组账号。普通好友添加不建立课题组关系。
2. 工作台“创建科研计划”：手工编辑或使用科研模板；AI 拆解需自己的默认模型。明确每步目标、交付和验收标准，再保存 / 确认；修改标题或顺序不丢失步骤与任务关联。
3. 选择学生形成待接受邀请。学生明确接受并开始，缺少材料时记录阻碍和需要的支持，解决后确认继续。
4. 学生提交实际成果摘要和允许的附件引用。导师审阅最新版本，给出修改意见或明确验收。要求修改后学生重新提交新的修订版。
5. 总览显示当前获准范围的汇总，本页筛选 / 搜索和成员承接。已确认截止才计算逾期；建议日期不计承诺。读取失败显示重试，不能当成没有任务。

## 接口和边界

`GET /api/v1/labs/{id}/research-workspace`：`scope=lab|mine`、`limit`、`cursor`、`snapshot`。先按任务 ACL 过滤再计算全部获准范围汇总和分页；返回任务投影、获准最新交付和实际分工。摘要账号没有私人计划、交付正文或分工详情。只有已完成且最新真实交付 / 审阅均为 accepted 才计验收。

`GET /api/v1/plans/{id}/tasks`：计划所有者授权后，以已有 `(plan_id,item_id)` 唯一关联返回步骤任务；失去任务权限时编号与投影均为空。无需新表或迁移。

新私人规划持久绑定发起人默认模型的 provider、model、source、fingerprint。普通成员没有自己的配置时明确失败，不用另一人的 Key；无个人设置的实验室管理员保留旧实验室配置。运行期间更换或停用配置会停止旧请求，晚到草稿不写回，实际用量保留。历史无绑定任务按原实验室路径，公共任务运行不改变配置来源。

聊天当前请求通过消息 ID 或完整协调文本定位；旧文件只在明确引用 / 选择或紧接文件的续问中使用。未选择的旧文件派生回复退出普通近期 / 历史模型材料，但消息没有从数据库或界面删除。旧来源 ACL、记忆撤回与预算检查保持。
