# Personal Agent first batch (0.18 / chat1.7)

All routes use normal cookie session, Origin, CSRF and keyed mutation envelopes. All response objects are wrapped in `{data:...}`; lists add `nextCursor`. Exact exports live in `src/personal-assistant.ts`.

- `personalMemorySettings` GET `/me/memory-settings`; POST `updatePersonalMemorySettings` with `{expectedVersion,candidateLearning,timeZone,quietHours}`. Candidate learning defaults false; timezone defaults visible `Asia/Shanghai`. Quiet hours null or `{start:"22:00",end:"08:00"}`.
- `personalMemories` GET `/me/memories?status=all|confirmed|candidate|revoked&limit&cursor`; `personalMemory` GET `/me/memories/{id}`. Memory has `id,topic,content,scope:"general"|"topic",status,origin:"explicit"|"feedback"|"inferred",sourceMessageId,version,createdAt,updatedAt,allowedActions`.
- `createPersonalMemory` POST `/me/memories` with `{topic,content,scope}`. Corrects existing confirmed topic instead of duplicating it. `updatePersonalMemory` POST `/me/memories/{id}` adds expectedVersion. `decidePersonalMemory` POST `/me/memories/{id}/decision` with `{expectedVersion,decision:"confirm"|"revoke"}`. Candidate records are not model context until confirmed; corrections/revocations are versioned and auditable.
- `personalFollowups` GET `/me/followups?status=all|active|paused|completed|cancelled&limit&cursor`; `personalFollowup` GET `/me/followups/{id}`. `createPersonalFollowup` POST `/me/followups` with `{title,body,dueAt,timeZone,task:null|{id,version},quietHours:null|{start,end}}`. `updatePersonalFollowup` POST `/me/followups/{id}` adds expectedVersion. `changePersonalFollowup` POST `/me/followups/{id}/state` with `{expectedVersion,action:"pause"|"resume"|"complete"|"cancel"}`.
- Followup projection includes canonical `messageId` and actual `delivery:"scheduled"|"due"|"recorded"|"im_sent"|"im_uncertain"|"im_denied"`. A recorded service message is not proof of IM delivery or phone push. One-time reminders never repeat after their canonical message is written. Due worker is persistent, transactional and needs no LLM. Optional task requires current full task ACL; completed/cancelled tasks stop followup.

AgentTurn optional new metadata (absent on ordinary old replies):

```
memoryReceipt: {operation:saved|corrected|forgotten|candidate|clarify,
 memoryId:null|string,topic:null|string,status:null|confirmed|candidate|revoked,
 version:number,question:null|string}
followupReceipt: {operation:created|clarify,followupId:null|string,
 dueAt:null|instant,timeZone:null|string,question:null|string}
assistantReceipt:
 {kind:delegate,contactId,conversationId,displayName,reused,messageId,turnId,
  status:queued|unavailable,budget:{maxTokens,maxSeconds}}
 | {kind:collaborate,planId,actionIds}
```

Receipts describe saved objects, not SDK connection or completed work. Delegation is only to own available local specialists; current user request is copied to the canonical owned direct and a real child turn is queued with remaining parent budget. `status` and `budget` describe the initial handoff; read the authorized child turn for live status. Parent receipt projection follows that message's latest retried child in the same owner/root/direct. No external contact/key is selected; requester current text grants this scope, not quoted documents/history/profile/model instructions. Existing explicit creation flow is retained. Complex proposals use existing plan/action confirmation; people still accept independently. Accepted humans in the same lab may be proposed; cross-workspace friends are still private-chat contacts, and receive an explicit unsupported collaboration explanation instead of an invented group.

Natural explicit preference heads include `记住...`, `以后回答/回复请...`, `纠正偏好...`, `忘记...`; one-time `这次...` is not permanent. Common dimensions have stable topics; unclassified explicit facts have independent content topics. `回答方式/回复风格` normalize to `回复方式`, `名字` to `称呼`. Ambiguous correction/forget target clarifies; `[topic]: content` permits a precise target. Candidate confirmation explicitly replaces confirmed same-topic preference and retains the original source. Current own local private chat may manage own user memory; files never grant this operation. Natural reminders accept `明天上午九点提醒我交材料`, today/tomorrow/day-after or a full local date and time, using the visible member timezone; explicit ISO timestamps with offsets also work. Missing time, invalid calendar dates and DST gaps/overlaps clarify with the time picker; responses display Chinese local time. All deterministic management works without a configured model.

Current work heads include `帮我/给我/请…分析/看看/研究/阅读/整理/修改/写/规划/安排…`, `我想研究…`, and `我需要一个能…`. Capability questions, negations and quoted/example heads stay ordinary conversation. This first batch does not claim unrestricted natural-language intent understanding. Coordination uses the full current request, current profile, authorized memories and complete role candidates ranked by textual relevance; up to three fit the existing budget, with explicit `specialistsOmitted`. The model must ask rather than assume an omitted directory has no suitable role. Normal daily chat retains its existing bounded history selection.

Confirmed personal memories are separate from old Agent/private_agent memories. Only own local personal/direct chats receive relevant general/topic records; group, another person's Agent and external wire receive none. Context records carry source/scope and are version-fenced; no implicit summarization or truncation of authorized current fields. Candidate learning creates reviewable inferred candidates only when enabled. Model/result cannot independently save a preference.

Migration018 adds `personal_memory_settings`, `personal_memories`, `personal_memory_revisions`, `personal_followups` and indexes only. New turn metadata lives in private request_json and authorized projections; persisted strict message/turn documents keep old shapes. New deterministic/coordinating roots and delegated children carry `personalAssistant:true`; children retain the parent's `root_id`. Old code cannot simply start on schema18; recovery must preserve the current database, pause active unfired followups and fence pending Personal Assistant roots/children before a compatible old behavior image starts. Isolated restore disables learning, advances its fingerprint, pauses unfired reminders and marks pending/in-flight IM outbox records uncertain instead of replaying them. Cancel/complete stop future canonical notifications and pending IM intents; notifications already in transit or sent are not claimed recalled.
